# 多 Agent 协同决策

## 协同决策的概念

多 Agent 协同决策是指多个专业 Agent 通过信息交换和协商，共同做出比单个 Agent 更优的决策。每个 Agent 贡献自己的专业视角，最终的决策是多方信息融合的结果。

## 为什么需要协同决策

单个 Agent 的视角有局限：
- 诊断 Agent 知道学习者缺什么，但不知道能生成什么
- 生成 Agent 能产出内容，但需要诊断信息来个性化
- 审核 Agent 能检查错误，但需要诊断信息判断难度是否匹配

只有通过协同，三个 Agent 的信息被充分利用，才能产出"准确 + 个性化 + 高质量"的学习资源。

## 协同决策流程

以学习者答题后调整学习路径为例：

```
学习者提交答题结果
     ↓
Agent 1 重新评估知识水平（基于答题表现）
     ↓
Agent 3 分析答题错误模式（哪些盲区仍然存在）
     ↓
Agent 2 根据新诊断决定下一步内容
     ↓
三个 Agent 共同决策：继续 / 简化 / 进阶 / 重新生成
```

## 决策类型

### 1. SIMPLIFY（简化）
触发条件：
- 答题正确率 < 40%
- Agent 3 发现难度过高
- 学习者行为数据表明认知负荷过大

决策：降低一个难度级别，重新生成资源。

### 2. ADVANCE（进阶）
触发条件：
- 答题正确率 > 90%
- Agent 1 检测到知识盲区已消除
- 当前难度级别的内容对学习者不再有挑战性

决策：提升一个难度级别。

### 3. REGENERATE（重新生成）
触发条件：
- Agent 3 检测到幻觉率超标（> 5%）
- 盲区覆盖率不达标（< 90%）
- 学习者明确反馈内容不满意

决策：修改生成参数后重新执行生成流水线。

### 4. CONTINUE（继续）
触发条件：所有指标达标，按原计划继续。

## 投票机制

当 Agent 意见不一致时，采用加权投票：
- 事实准确性：Agent 3 的权重最大
- 难度判断：Agent 1 的权重最大
- 内容质量：Agent 3 + 用户反馈共同决定

## 协同日志

所有决策过程都有完整日志，支持回溯：
```json
{
    "decision": "simplify",
    "reason": "答题正确率35%，低于阈值40%",
    "contributing_agents": ["诊断Agent", "审核Agent"],
    "agent1_vote": "simplify",
    "agent3_vote": "regenerate",
    "final_rationale": "多数一致：内容过难，先简化"
}
```

## 设计原则

1. **透明性**：每个决策都可以追溯到具体的 Agent 意见
2. **可覆盖**：学习者和教师可以覆盖系统决策
3. **有边界**：关键决策（如难度大幅跳跃）需要多方确认
4. **持续学习**：决策结果反馈到系统，持续优化
