# RAG 检索增强生成

## 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是一种将**信息检索**与**文本生成**相结合的技术架构。在 LLM 生成答案之前，先从外部知识库中检索相关信息，将其作为上下文注入 prompt，从而显著减少幻觉（Hallucination）。

## RAG 架构

标准的 RAG 流水线包含三个阶段：

### 1. 索引阶段（Offline）
- 收集领域文档
- 将文档切分为适当大小的 chunk
- 使用 embedding 模型将每个 chunk 转换为向量
- 将向量存入向量数据库

### 2. 检索阶段（Online）
- 接收用户查询
- 将查询转换为向量（使用相同的 embedding 模型）
- 在向量数据库中检索最相似的 Top-K 个 chunk
- 返回相关文档片段

### 3. 生成阶段（Online）
- 将检索到的文档片段拼接到 prompt 中
- LLM 基于检索到的上下文生成答案
- 可选：提供引用来源

## 为什么 RAG 能减少幻觉

LLM 的幻觉主要来自两个来源：
1. **知识截止日期**：模型训练数据有截止时间
2. **记忆模糊**：模型参数中存储的知识可能不精确

RAG 通过提供**可验证的外部知识**来解决这两个问题。LLM 不再依赖参数记忆，而是基于检索到的原文生成答案。

## 关键设计决策

### Chunk 大小
- 太小的 chunk 丢失上下文
- 太大的 chunk 引入噪声
- 推荐 256-512 字符，overlap 50-100 字符

### 检索数量（Top-K）
- Top-K 太小：可能遗漏关键信息
- Top-K 太大：上下文过长，LLM 可能忽略重要内容
- 推荐 K=3-5

### 相似度阈值
- 阈值太低：引入不相关内容
- 阈值太高：可能找不到任何结果
- 推荐 min_similarity=0.6-0.7

## 高级 RAG 技术

### 父文档检索
存储两种粒度的文档：小 chunk 用于精确检索，大 chunk（父文档）用于提供完整上下文。

### 多路检索
同时使用向量检索和关键词检索（BM25），合并两者的结果，互补各自的局限。

### Self-RAG
让 LLM 在生成过程中自我判断是否需要检索，以及检索结果是否相关。

### Corrective RAG
在生成答案后，自动评估答案的事实准确性，如果不达标则触发重新检索和生成。

## RAG 评估指标

- **忠实度（Faithfulness）**：生成的答案是否完全基于检索到的上下文
- **相关性（Relevance）**：检索到的文档与问题的相关程度
- **覆盖率（Coverage）**：检索结果是否覆盖了回答问题所需的所有信息
