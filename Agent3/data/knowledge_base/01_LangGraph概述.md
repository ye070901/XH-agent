# LangGraph 概述

## 什么是 LangGraph

LangGraph 是 LangChain 团队推出的一个开源库，专门用于构建**有状态的、多角色的 LLM 应用**。它的核心思想是将复杂的 AI 任务建模为**状态图（StateGraph）**，其中每个节点代表一个处理步骤，边代表数据流向。

与传统的单体 LLM 调用不同，LangGraph 允许开发者：
- 将任务拆分为多个独立的步骤
- 每个步骤可以调用不同的 LLM 或工具
- 通过状态字典在步骤间传递数据
- 根据中间结果动态选择执行路径

## 核心概念

### StateGraph

StateGraph 是 LangGraph 最核心的抽象。它本质上是一个有向图，包含三个基本要素：

1. **节点（Node）**：执行具体任务的函数或 LLM 调用
2. **边（Edge）**：定义节点之间的数据流向
3. **状态字典（State）**：在节点之间传递的共享数据结构

### 状态管理

LangGraph 使用 TypedDict 或 Pydantic 模型来定义状态结构。每个节点接收当前状态，返回更新后的状态。这种设计确保了数据流是可预测和可追踪的。

```python
from typing import TypedDict

class AgentState(TypedDict):
    messages: list
    next_step: str
    result: dict
```

### 节点类型

- **普通节点**：执行任意 Python 函数
- **LLM 节点**：调用大语言模型
- **工具节点**：调用外部工具或 API
- **条件节点**：根据状态决定下一步路由

## 与传统方法的对比

| 特性 | 传统单体 LLM | LangGraph |
|------|-------------|-----------|
| 复杂度控制 | 单次调用完成所有任务 | 分步骤，每个步骤职责单一 |
| 可调试性 | 难以追踪中间决策 | 每一步状态变化可观测 |
| 工具集成 | 依赖 prompt 工程 | 原生支持工具调用节点 |
| 错误恢复 | 从头重试 | 可从失败节点恢复 |
| 多角色协作 | 难以实现 | 多 Agent 天然支持 |

## 适用场景

- 需要多步骤推理的复杂问答系统
- 涉及多个外部工具的自动化工作流
- 需要人工审核介入的流程
- 多 Agent 协同决策系统
- RAG（检索增强生成）流水线

## 学习路径建议

1. 先理解 StateGraph 的基本概念（节点、边、状态）
2. 学习如何定义状态类型（TypedDict / Pydantic）
3. 掌握节点的编写方式（函数、LLM 调用、工具调用）
4. 理解条件路由的工作原理
5. 实现一个简单的 2-Agent 协同系统
6. 逐步扩展到更复杂的多 Agent 架构
