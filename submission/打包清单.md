# 提交包打包清单（更清晰版）

> 对应题目「八、作品提交方式」：材料文档 + 软件模块(源码) + 测试数据 **统一打包压缩**，
> 压缩包命名 `申报人所在学校—申报人姓名—作品名称—联系电话`。

## 一、最终 zip 结构（三项并列，评委顶层可见）

```
<学校>—<姓名>—<作品名称>—<电话>.zip
├── 01_材料文档/     ← 手动放入：作品设计实现方案、作品介绍、PPT、≤10 分钟演示视频
├── 02_软件模块/     ← pack.py 自动：仓库源码导出（排除 .git/.venv/chroma 等派生文件）
└── 03_测试数据/     ← pack.py 自动：submission_test_data 副本（切片+画像+输入输出示例）
```

## 二、各项目前状态

| 项 | 状态 | 说明 |
|----|------|------|
| 01 材料文档 | ⚠️ 待补 | 方案文档/PPT/视频还没放进来，见 `01_材料文档/README.md` |
| 02 软件模块 | 🔨 开发中 | 幻觉率调优进行中，源码未冻结 |
| 03 测试数据 | 🔨 开发中 | 三组样例是当前系统快照，幻觉率调完后需重跑刷新 |

## 二点五、材料文档放哪里（重要）

材料文档分两类放，**别全塞 git 仓库**：

| 材料 | 放哪 | 是否进 git |
|------|------|:---:|
| 方案文档（.md / .docx） | 仓库 `docs/` 或 `submission/01_材料文档/` | ✅ 进（文本可版本管理） |
| PPT（.pptx） | `submission/01_材料文档/` | ⚠️ 可选（几 MB，能放但 diff 难看） |
| 演示视频（.mp4 等） | 本地 `submission/01_材料文档/` | ❌ **不进 git**（几十~几百 MB，撑爆仓库） |

- 视频等大文件**留本地**，打包时已经放好在 `submission/01_材料文档/` 里即可；
- `.gitignore` 已忽略 `submission/01_材料文档/` 下的 `*.mp4 / *.mov / *.avi / *.zip`，防止误提交；
- 打包脚本 `pack.py` 只读 `submission/01_材料文档/` 现有文件，不关心它们是否被 git 跟踪。

## 三、提交前操作顺序（重要）

1. **等幻觉率调优完成**（别人正在测）。
2. 重跑三组端到端样例（后端已起时）：
   ```bash
   python submission_test_data/_build/generate_samples.py
   python submission_test_data/_build/build_package.py
   ```
3. 刷新提交包的测试数据副本：
   ```bash
   python submission/pack.py --only-testdata
   ```
4. 把方案文档、PPT、演示视频放进 `submission/01_材料文档/`。
5. 改 `submission/pack.py` 顶部的 `SCHOOL / AUTHOR / TITLE / PHONE` 为真实值。
6. 打包：
   ```bash
   python submission/pack.py
   ```
   产出 `submission/<学校>—<姓名>—<作品>—<电话>.zip`。

## 四、别忘的既有待办（来自打包方案）

- 提交前清理运行时垃圾（.coverage、logs、data/chroma.bak 等）。
- 修正 README 快速启动章节里的脚本路径。
