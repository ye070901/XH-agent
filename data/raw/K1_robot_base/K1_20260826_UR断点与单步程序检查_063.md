## 正文

### 1. 调试目标与版本边界

本篇要解决的具体问题是：用 Breakpoint 和 Single Step 找出变量或节点首次偏离预期的位置。依据版本为 PolyScope 5 Software Handbook SW 5.23；不同软件版本的菜单与功能可能变化。界面名称、默认值和可选功能可能随控制器、选件或软件版本变化，实际操作前应以机器人铭牌、当前系统版本和已批准的现场作业指导书为准。本文聚焦可观察、可回退的基础操作，不讨论伺服控制原理、运动学正逆解推导或控制器底层内核。

断点用于暂停并检查状态，单步按节点推进；靠近机器人时仍必须遵守手动模式、使能和速度限制。调试记录至少应包含程序/安装文件名、工具与工件坐标、速度倍率、输入输出初始值、操作者和验证结果，便于问题复现与回滚。

### 2. 操作前安全检查

本文仅用于经过培训和授权人员的基础调试。首次验证应在手动模式、低速度倍率、工作区清空且风险评估与现场安全措施有效的条件下进行。普通程序 I/O、Stop、Popup 或软件逻辑均不能替代急停、门锁、安全 PLC、限速/限位等经验证的安全功能。

开始前先备份当前程序或安装文件，核对机器人处于正确操作模式，确认 TCP、载荷、工件坐标和信号名称与现场一致。若下一步动作方向不明确，应保持电机禁止或使用离线副本核对，不得靠连续试动猜测。任何报警都应先阅读事件文本并记录时间，不要反复复位后继续。

### 3. 完整操作步骤

1. **建立安全基线**：确认急停与防护装置可用，工作区无人，工具、工件和外围设备处于受控状态；把速度倍率降至 10% 以下。
2. **准备对象**：保存程序副本，在怀疑节点前设置断点，并把真实工艺输出隔离。
3. **实施设置**：运行到断点后查看 Variables、I/O 与 Log，再逐节点单步。
4. **首次执行**：先做语法或节点检查，再从规定起始位置单步运行；每一步都观察机器人、I/O、变量和程序指针。
5. **结果验证**：记录每一步的输入、输出和变量，找到第一处不符合预期的节点后停止修改范围扩散。
6. **保存与回退**：保存验证通过的版本并记录变更；若结果异常，停止执行、恢复原值或备份文件，未经复核不切换自动运行。

### 4. 可执行验证示例

以下示例用于说明本文的最小验证逻辑。真机运行前必须把示例中的点位、信号、TCP、Feature 或数据名称替换为现场已审核对象，并在仿真或手动低速模式验证。

```Python
trace=[('before_if',False,0),('after_input',True,0),('after_count',True,1)]
first_change=next(i for i in range(1,len(trace)) if trace[i][1:]!=trace[i-1][1:])
print('first state change index:',first_change)
```

### 5. 验收标准与故障排查

验收时应同时满足：程序或节点能通过检查；从规定起始状态运行三次结果一致；没有未处理报警；机器人路径、末端姿态、变量和普通 I/O 均符合记录；停止或异常分支能把设备保持在可恢复状态。只要出现一次意外运动、信号反相、配置不一致或无法解释的报警，就应判定本轮不合格并回退。

常见问题处理：断点未命中时检查节点是否处于实际执行分支；单步前确认机器人下一动作方向和周边安全。排查遵循“先状态、再配置、后程序”的顺序：先看机器人模式与事件日志，再核对 TCP/载荷/坐标/信号映射，最后定位到具体指令或节点。禁止通过关闭安全功能、扩大限制或强制未知信号来消除报警。

## 适用场景

本文可用于 XH-agent 工业机器人调试辅助系统的**学情诊断 Agent**（判断用户是否掌握该操作的前置条件与验收点）、**检索回答生成**（按版本和厂商返回可执行步骤）、**故障排查指导**（根据现象定位状态、配置或程序问题）以及**安全规范检查**（识别跳过低速验证、缺少回退、把普通 I/O 当作安全功能等不合规操作）。
