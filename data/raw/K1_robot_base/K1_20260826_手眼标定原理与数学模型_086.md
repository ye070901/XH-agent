## 正文

### 1. 为什么需要手眼标定

视觉测得的目标位置在相机坐标系下，而机器人要在自身坐标系中运动。若不知道相机与机器人之间的变换关系，视觉引导就无法落到机器人动作上。手眼标定就是求解这个固定（或随末端运动）的刚体变换矩阵。

### 2. 两种配置与数学表达

#### Eye-in-Hand（眼在手上）

相机固定在机器人末端，随末端运动。设：

- $T_{cam}^{tool}$：相机相对末端的固定变换（待求）；
- $T_{tool}^{base}$：末端相对基座的变换（机器人正解给出）；
- $T_{obj}^{cam}$：标定板相对相机的变换（视觉解算给出）；
- $T_{obj}^{base}$：标定板相对基座的世界固定位姿。

对两次不同位姿建立方程：

```
T_cam^tool · T_tool^base(i) · T_obj^cam(i) = T_cam^tool · T_tool^base(j) · T_obj^cam(j)
```

整理后化为经典 AX = XB 形式：A 由机器人两次位姿构成，B 由相机两次观测标定板位姿构成，X 即待求的相机-末端变换。

#### Eye-to-Hand（眼在手外）

相机固定在工作空间外，末端夹持标定板移动。此时待求的是相机相对机器人基座的变换 $T_{cam}^{base}$，同样可化为 AX = XB 问题，A/B 的构造由末端运动与相机观测共同给出。

### 3. 数学求解要点

- AX = XB 通常先求旋转部分，再求平移部分；
- OpenCV `calibrateHandEye` 提供多种求解方法（如基于四元数/李群的方法），输入为多组机器人末端位姿与标定板-相机位姿（`robot_to_world`/`world_to_camera` 等）；
- 需要足够多且运动差异大的位姿才能得到稳定解。

### 4. 可执行验证思路（OpenCV 风格）

```python
import cv2
# 采集 N 组：机器人末端位姿 R_gripper2base/t_gripper2base
#           标定板位姿 R_target2cam/t_target2cam
R_cam2gripper, t_cam2gripper = cv2.calibrateHandEye(
    R_gripper2base, t_gripper2base, R_target2cam, t_target2cam)
# 将标定板下目标点经该变换转换到末端/基座坐标
```

### 5. 精度影响因素与验证

| 因素 | 影响 |
|------|------|
| 位姿运动范围 | 旋转差异太小，解病态 |
| 标定板目标检测精度 | 直接注入 AX=XB 噪声 |
| 机器人位姿精度 | 机器人绝对精度误差直接影响结果 |
| 内参标定质量 | 先做好相机内参再手眼标定 |

验证：用标定点回投影检查误差（将相机观测到的工作目标转到机器人坐标后与机器人实际姿态比对）；残差大则增加位姿样本并确保运动分散。
