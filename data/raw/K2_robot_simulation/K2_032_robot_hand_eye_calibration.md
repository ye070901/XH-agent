## 正文

离线程序在真机上跑偏，九成原因是**坐标系没对齐**。核心标定包括：工具坐标（TCP）、基坐标（BASE/UFRAME）、以及视觉引导中的**手眼标定**（相机与机器人末端的位姿关系）。

### 一、TCP 标定

1. 在示教器选择 TCP 标定（如 ABB 四点法 / FANUC 六点法）。
2. 用机器人末端工具以**不同姿态**触碰同一固定参考点。
3. 控制器解算出工具中心相对法兰的位置，写入 `tool` 数据。

### 二、基坐标系（BASE）标定

1. 三点法：在工件上取原点、X 轴点、XY 平面点。
2. 控制器据此建立工件坐标系（ABB `wobj`、FANUC `UFRAME`、KUKA `BASE`）。
3. 离线编程时必须在仿真中**复现同一坐标系**，真机轨迹才能对齐。

### 三、手眼标定原理（AX=XB）

- **眼在手上（Eye-in-Hand）**：相机装在机器人末端，求解相机相对末端的固定变换 X。
- 机器人做多组已知运动，记录每组**末端相对基座**的变换 A 与**标定板相对相机**的变换 B，满足 `AX = XB`。

```python
import cv2
import numpy as np

# R_gripper2base, t_gripper2base: 机器人末端位姿（N 组）
# R_target2cam, t_target2cam: 标定板在相机下的位姿（N 组，由 solvePnP 得到）
R, t = cv2.calibrateHandEye(
    R_gripper2base, t_gripper2base,
    R_target2cam, t_target2cam,
    method=cv2.CALIB_HAND_EYE_TSAI
)
print("相机相对末端旋转:", R)
print("相机相对末端平移:", t)
```

### 四、标定数据采集要点

| 要点 | 说明 |
|------|------|
| 姿态多样 | 至少 10~15 组，覆盖大范围旋转/平移 |
| 标定板清晰 | 标定板始终在相机视野内、成像清晰 |
| 避免共线 | 各次运动方向不能过于接近 |
| 用 TSAI 或 Park 法 | 数值稳定，工业常用 |

### 五、常见问题

| 现象 | 原因 | 对策 |
|------|------|------|
| 视觉抓取偏移 | 手眼标定误差 | 增加采样组、重新标定 |
| 离线轨迹整体偏 | TCP/BASE 未对齐 | 真机重新标定 TCP 与 UFRAME |
| 标定结果发散 | 采样姿态退化 | 增大姿态多样性 |

## 适用场景

本文用于 XH-agent 回答"手眼标定怎么做""离线轨迹为什么跑偏"等问题，是 K2 故障排查与视觉集成的基础。
