## 正文

### 一、故障分类总览

离线编程仿真环境虽然避免了真机上的物理损坏风险，但仿真本身的错误同样会浪费大量时间。以下 7 类故障是各品牌（ABB/KUKA/FANUC）离线编程中共同的高频问题。

### 二、7 大类故障详解

---

#### 故障 1：奇异点错误（Singularity Error）

**症状**：
- 仿真运行到某点位时机器人突然停止，控制器报 "Close to singularity" 或 "Joint 5 near zero"
- 关节 4 和关节 6 出现异常大角度旋转
- 仿真界面弹出 "无法求解逆运动学" 错误

**根因分析**：
当机器人腕关节对齐（J5 ≈ 0°）时，J4 和 J6 的旋转轴重合，逆运动学有无穷多解，控制器无法选择唯一配置。这是 6 轴串联机器人的固有数学特性，非软件 bug。

**可执行修复步骤**：

1. **识别奇异点位置**：
   - ABB RobotStudio：运行仿真 → 查看 TCP 跟踪 → 寻找轨迹异常拐点
   - KUKA.Sim：启用"Singularity Visualization"→ 红色区域即为奇异点
   - FANUC ROBOGUIDE：Reachability Check → 黄色标记

2. **修复方法 A — SingArea 配置（ABB）**：
   ```rapid
   SingArea \Wrist;          ! 允许手腕通过奇异点时选择替代解
   MoveL pProblematic, v500, z10, tTool;
   SingArea \Off;            ! 通过后关闭（非必要不启用）
   ```

3. **修复方法 B — 调整目标点位姿（通用）**：
   - 将目标点 TCP 沿运动方向偏移 5~10mm
   - 旋转目标点姿态角 A/B/C（KUKA）或四元数（ABB）5~10°
   - 插入一个中间过渡点（PTP 方式通过奇异区域，而非 LIN）

4. **修复方法 C — 修改路径规划策略**：
   - 将 LIN 运动改为 PTP（关节空间规划不受笛卡尔奇异影响）
   - 添加冗余运动：稍微偏离直线路径 20~30mm 绕过奇异区域

#### 故障 2：程序指针丢失（Program Pointer Lost）

**症状**（ABB RobotStudio 特有）：
- 使用 "Move Along Path" 功能仿真后，弹出 "Program Pointer Lost" 错误
- 程序指针消失，示教器显示 "No program selected"

**根因分析**：
RobotStudio 的 "Move Along Path" 会创建临时模块（`TMP_xxx`），将路径点序列写入该模块后执行仿真，仿真完成后自动删除临时模块。程序指针绑定到已删除的模块上，因此触发 "lost" 消息。

**可执行修复步骤**：
1. **判断是否为无害误报**：如果在 "Move Along Path" 仿真完成后立即弹出此消息 → 直接忽略，不是实际故障
2. **正常仿真方式**：不要用 "Move Along Path" 做全流程仿真，应：
   - 将路径点正式添加到 RAPID 程序的目标点数组中
   - 编写完整的 `PROC main()` 程序
   - 通过"仿真"→"播放"而非 "Move Along Path" 运行
3. **恢复程序指针**：
   ```
   示教器 → Program Editor → Debug → PP to Main
   → 选择目标 Routine → 程序指针恢复
   ```

#### 故障 3：仿真-真机偏差（Calibration Gap）

**症状**：
- 仿真中机器人运动完全正常，下载到真机后点位全部偏移
- 真机上 TCP 位置与预期偏差 5~50mm
- 抓取/放置时有碰撞或错位

**根因分析**：
仿真模型中的坐标系与真实工作单元的坐标系不一致。常见原因：
1. BASE 坐标系未正确标定（仿真用理论值，真机需实测）
2. TCP 标定误差大（> 3mm）
3. 工件/夹具的安装位置与 CAD 模型有偏差

**可执行修复步骤**：

1. **BASE 坐标系对齐（标准操作）**：
   ```
   ABB: 真机上用 3 点法标定 wobjdata
   KUKA: 真机上用 3 点法标定 BASE_DATA[n]
   FANUC: 真机上用 3 点法标定 UFRAME[n]
   ```

2. **仿真与真机坐标系同步**：
   - 仿真中使用"零位参考法"：示教真机上 3 个特征点 → 测量坐标 → 回填到仿真模型中修正 BASE
   - 使用激光跟踪仪做高精度标定（大型工件场景）

3. **TCP 标定验证**：
   - 真机 TCP 标定后用 4 种不同姿态触碰同一固定点
   - 偏差应 < 2mm（搬运）或 < 0.5mm（精密装配）

4. **快速偏移修正法**：
   ```rapid
   ! 真机上实测偏移量后，统一修正所有目标点
   pAllTargets{n} := Offs(pAllTargets{n}, dx, dy, dz);
   ```

#### 故障 4：运动路径错误（Path Error）

**症状**：
- 仿真中机器人走出的路径与预期不符（弯曲 / 绕远路 / 姿态异常）
- 碰撞检测意外触发
- 末端执行器在运动中出现奇怪翻转

**根因分析**：
| 可能原因 | 具体表现 |
|----------|----------|
| zonedata/逼近参数过大 | 路径拐角被大幅平滑，绕过障碍物约束失效 |
| 轴配置（cf1/cf4/cf6）错误 | 机器人以"翻转"姿态到达目标点 |
| 工件坐标切换遗漏 | 目标点基于错误的 wobjdata/UFRAME |
| S/T 参数（KUKA）错误 | 腕关节旋转方向与预期相反 |

**可执行修复步骤**：

1. **检查转弯半径**：
   ```rapid
   MoveL pCritical, v200, fine, tTool;  ! 关键点位用 fine（精确到位）
   ```
   非关键路径才用 z10/z50 平滑过渡。

2. **检查轴配置（ABB）**：
   ```rapid
   ! 查看目标点的 cf1/cf4/cf6 参数
   CONST robtarget pTest := [[500,200,50],[0.707,0,0.707,0],[0,0,0,0],[9E9,9E9,9E9,9E9,9E9,9E9]];
   ! cf1=-1 或 1：轴 1 正/反方向到达
   ! cf4=-1 或 1: 轴 4 正/反方向
   ! cf6=-1 或 1: 轴 6 正/反方向
   ```

3. **KUKA S/T 参数逐项检查**：
   ```
   S: 二进制 010010 → 轴 1=0, 轴 2=1, 轴 3=0, 轴 4=0, 轴 5=1, 轴 6=0
   T: 每个轴的圈数（0=0 圈, 1=±1 圈依 S 符号）
   S/T 错误 → 重新示教该点让控制器自动计算正确的 S/T
   ```

#### 故障 5：I/O 通信故障

**症状**：
- 程序中 `WaitDI`/`WAIT FOR` 永远等不到信号，仿真卡住
- 数字输出置位/复位后外部设备（夹爪/输送带）无响应
- Smart 组件的传感器信号无法传递到 RAPID/KRL 程序

**根因分析**：

| 仿真平台 | 常见原因 |
|----------|----------|
| ABB RobotStudio | Smart 组件信号未映射到 I/O 板地址 |
| KUKA.Sim | 虚拟 I/O 模块未在 WorkVisual 中配置 |
| FANUC ROBOGUIDE | I/O 仿真面板未开启或信号地址不正确 |

**可执行修复步骤**：

1. **ABB RobotStudio Smart 组件信号映射**：
   ```
   Smart 组件 → 属性与绑定 → Signals
   → 添加 I/O Signals（如 diPartSensor / doConveyorEnable）
   → 工作站信号 → 将 Smart 信号连接到虚拟控制器的 I/O 地址
   ```

2. **ABB I/O 配置验证**：
   ```rapid
   ! 查看当前 I/O 板配置
   IODEVICE → 确认 d652（虚拟 I/O 板）已激活
   ! 信号声明
   CONST signaldo doGrip := 1;   ! DO[1]
   CONST signaldi diSensor := 3;  ! DI[3]
   ```

3. **FANUC ROBOGUIDE I/O 仿真面板**：
   ```
   Teach Pendant → I/O → Digital → 手动置位/复位测试
   → 确认 DI/DO 地址与实际接线一致
   ```

4. **通用调试技巧——逐步 I/O 跟踪**：
   - 在程序中每个 I/O 操作后添加 0.5 秒延时
   - 仿真运行到每一步，手动检查 I/O 状态面板
   - 信号异常 → 追踪信号源（Smart 组件 / PLC 模拟器 / OP 面板）

#### 故障 6：时序与同步延迟（OPC UA / 外部通信）

**症状**：
- 仿真软件通过 OPC UA 发送轨迹点给真实控制器，机器人运动出现滞后
- 轨迹点堆积 → 机器人运动卡顿或跳跃
- 仿真中读取的关节角度与实际不符

**根因分析**：
仿真软件（如 Visual Components）的 Python 脚本运行速度远快于机器人实际运动速度。在机器人完成上一个目标点之前，新的目标点已发送，导致指令堆积。

**可执行修复步骤**：

1. **添加同步等待**：
   ```python
   # Visual Components Python 脚本中
   import time
   for target in path_targets:
       robot.move_to(target)
       # 等待机器人到达目标点后再发送下一个
       while robot.distance_to(target) > 5.0:  # 5mm 容差
           time.sleep(0.05)  # 50ms 轮询间隔
   ```

2. **调整 OPC UA 发布速率**：
   - 降低脚本发送频率至 10~20Hz（匹配机器人运动频率）
   - 每次发送前确认机器人在预期位置附近

3. **轨迹预缓冲模式**：
   - 一次性发送完整轨迹到控制器（而非逐点发送）
   - 控制器内部做 Look-Ahead 平滑
   - 适用于焊接等连续轨迹应用

4. **使用机器人原生接口替代 OPC UA**：
   - ABB：EGM（Externally Guided Motion，4ms 周期）
   - FANUC：HMI Device（高速位置指令接口）
   - KUKA：RSI（Robot Sensor Interface，12ms 周期）

---

#### 故障 7：软件配置参数异常

**症状**：
- 运动速度/加速度与预期不符（过快导致碰撞风险，过慢影响节拍）
- 工具负载参数错误导致运动抖动
- 路径规划模式导致的意外行为

**根因分析**：

| 参数 | 错误设置后果 |
|------|-------------|
| `speeddata` 过高 | 机器人到达目标点时过冲 |
| `zonedata` 全部 `fine` | 每个目标点完全停止 → 节拍显著增长 |
| 负载数据未设置 | 控制器使用默认 0kg → 加减速参数不匹配 |
| 加速度限制过低 | 运动平滑但节拍不达标 |
| 加速度限制过高 | 机器人抖动、电机过载警告 |

**可执行修复步骤**：

1. **速度配置分层策略**：
   ```rapid
   CONST speeddata vFast := [2000, 500, 5000, 1000];   ! 空载快速移动
   CONST speeddata vNormal := [1000, 300, 5000, 1000]; ! 带载正常移动
   CONST speeddata vFine := [100, 50, 5000, 1000];     ! 精确接近/放置
   ```

2. **负载数据正确配置**：
   ```rapid
   ! tool0 的负载数据（吸盘+工件）
   PERS tooldata tGripLoad := [
       TRUE,
       [[0, 0, 100], [1, 0, 0, 0]],
       [3.5,              ! 总质量 kg（工具 1.5 + 工件 2.0）
        [0, 0, 60],       ! 重心位置 mm
        [1, 0, 0, 0],     ! 惯性主轴方向
        0.5, 0.3, 0.2]    ! 主惯性矩 Ixx, Iyy, Izz
   ];
   ```

3. **仿真参数诊断脚本**：
   ```rapid
   ! 在仿真中运行，输出当前运动参数
   TPWrite "Speed: " \Num:=vNormal.v_tcp;
   TPWrite "Acc: " \Num:=vNormal.v_ori;
   ! 检查是否与预期一致
   ```

### 三、故障排查黄金流程

```
1. 复现故障 → 截图保存错误信息
2. 简化场景 → 隔离到单个运动段/单个 I/O 操作
3. 逐项排查 → 对照本文 7 类故障逐一排除
4. 增量修复 → 每次只改一个参数，立即测试
5. 记录经验 → 在程序注释中标记修复方案
```
