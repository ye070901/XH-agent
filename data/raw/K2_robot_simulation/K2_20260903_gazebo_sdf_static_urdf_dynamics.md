## 正文

### 1. `static` 的含义

在 Gazebo/SDF 中，模型 `static=true` 表示该模型不可移动，不由动力学引擎模拟；`static=false` 才进入动力学仿真。静态通常适合地面、围栏、固定工装等环境对象。把需要运动或受力的机器人/末端工具错误设为 static，会造成“控制器有命令但模型不动”或接触行为异常。

### 2. URDF 到 SDF 不是无损同义词

URDF 是机器人描述格式，SDF 的模型/世界表达更广。Gazebo 的 URDF 转换会把 `<gazebo>` 扩展内容插入生成的 SDF，用于插件和 SDF 特有属性。转换成功不等于所有物理语义都已正确表达；应查看运行时生成模型、插件日志和实际接触/关节行为。

### 3. 动力学计算至少依赖这些数据

| 数据 | 缺失或错误时的常见结果 |
| --- | --- |
| mass 与 inertia | 模型飞走、抖动、加速度不合理或求解不稳定 |
| collision geometry | 接触点错误、穿模、碰撞性能差 |
| joint limit / damping / friction | 关节越界、振荡、与真机阻尼差异过大 |
| 控制周期与控制器参数 | 跟踪滞后、数值发散或动作不连续 |
| 固定世界连接或 static 设置 | 基座漂移、模型完全不受控或不参与物理 |

惯量必须以 link 自身坐标系、质量单位和合理的惯性张量表达。不能用任意大数“压住”模型，也不能把仿真稳定误认为等同于真实机器人刚度和伺服响应。

### 4. 排错顺序

先确认模型不是 static、基座固定关系和重力设置正确；再逐链检查质量/惯量、碰撞几何和关节限制；最后检查 ros2_control 接口与控制周期。每次只改变一个可追溯参数，并记录仿真版本和观察结果。
