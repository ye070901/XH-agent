# 补库后金标准更新流程（Checklist）

> 用途：知识库补库后，如何正确更新评测指标与金标准，避免漏步、避免「金标准错位」。
> 背景数据（2026-09-03）：幻觉率 8.91% = 真编造 0.20%(1) + 检索未召回 2.57%(13) + 知识库空白 6.14%(31)，分母 505 条 positive 断言。

---

## 核心原则（先记牢）

1. **金标准锚定在「某一次模型输出」上**。只要重跑模型，断言文本就变，旧 claim_id 全部错位，必须重新锚定。
2. **补库本身不触发重做**；只有「重跑模型」才触发重新锚定。
3. **补库只影响「unverifiable」那批**，accurate / hallucination 不受影响（加库不会让「有据」变「无据」）。
4. **先轻量探路，再决定重跑**：先重核 unverifiable 看补得对不对，别直接花重跑的钱。

---

## 两条路线

| | 路线一：只补库不重跑 | 路线二：补库 + 重跑模型 |
|---|---|---|
| 目的 | 验证补库方向对不对 | 拿正式新幻觉率 |
| 成本 | 零 LLM 调用 | DeepSeek 74 case + 重新标定 |
| 金标准工作量 | 只重核 unverifiable | 全部重新锚定 + 重标 |
| 何时用 | 不确定补得对不对时 | 确认要提交正式数字时 |

---

## 路线一：只补库，轻量探路

### 步骤

1. **补库**：写新 `.md` 文档进 `data/raw/<领域>/`。
2. **引用同步**（铁律，见 CLAUDE.md §6）：
   - 新增/改名文档前，同步 `data/core_knowledge_map.json` 的 `source_documents`。
   - 全局 grep 该文档名，同步 `phase3_test_cases.json`、`gold_labels_*.json`、`qa_dataset/` 等所有引用。
3. **重核金标准里的 unverifiable**（脚本现成）：
   ```bash
   ./.venv/Scripts/python.exe scripts/reclassify_gold.py
   ```
   或 LLM 语义裁决（如需理解同义转述）：
   ```bash
   ./.venv/Scripts/python.exe scripts/llm_adjudicate.py
   ```
4. **看升级多少**：
   - 大量 unverifiable 升级 → 补对了，值得走路线二。
   - 几乎没升级 → 补错了地方，回头补对，别重跑。

> 注意：路线一**不改变**正式幻觉率（那是固化在 raw_outputs 里的）。它只回答「补库方向对不对」。

---

## 路线二：补库 + 重跑模型（拿正式数字）

### 步骤

1. **补库 + 引用同步**（同路线一步骤 1、2）。

2. **重启后端**（重新向量化新文档）：
   ```bash
   # 停掉旧后端进程，重启：
   ./.venv/Scripts/python.exe main.py
   # 健康检查（确认新文档被切块加载）：
   curl http://localhost:8000/health
   ```

3. **重新采集 raw_outputs**（生成 + 审核都基于新库）：
   ```bash
   ./.venv/Scripts/python.exe scripts/collect_phase3_outputs.py \
     --cases data/evaluation/phase3_test_cases_k1k7_70.json \
     --output data/evaluation/runs/phase3_raw_outputs_k1k7_70.v2.json \
     --mode eval --timeout 240
   ```

4. **重新评估**（拿新幻觉率 + 拆分口径）：
   ```bash
   ./.venv/Scripts/python.exe scripts/run_phase3_evaluation.py \
     --outputs data/evaluation/runs/phase3_raw_outputs_k1k7_70.v2.json \
     --output-report data/evaluation/runs/phase3_report_k1k7_70.v2.json \
     --cases data/evaluation/phase3_test_cases_k1k7_70.json \
     --gold-file data/evaluation/gold_labels_k1k7.json
   ```

5. **金标准重新锚定**（因为模型重跑，断言文本变了）：
   - 用报告里的 `gold_candidate_claims` 重新抽样：
     ```bash
     ./.venv/Scripts/python.exe scripts/build_extended_gold_draft.py \
       --report data/evaluation/runs/phase3_report_k1k7_70.v2.json \
       --sample-size 250 \
       --out data/evaluation/gold_labels_extended.draft.json
     ```
   - 证据检索 → 四态重标 → LLM 语义裁决 → 定稿（复用 `extract_evidence_snippets.py` / `reclassify_gold.py` / `llm_adjudicate.py`）。

6. **标定 + 三分类**：
   ```bash
   ./.venv/Scripts/python.exe scripts/classify_unverifiable.py
   ```

## 达标目标对照

| 指标 | 当前 | 目标 | 缺口 |
|---|---|---|---|
| 幻觉率（<5%） | 8.91% | <5% | 需转正 ≥21 条 unverifiable |
| 真编造率 | 0.20% | 越低越好 | 已优秀 |
| 知识库对齐率 | 91.1% | 越高越好 | — |

**达标路径**：修 13 条 MISS（改检索/prompt，零补库）+ 补 8 条 GAP（补库）。

---

## 风险提示

- **别用错位的旧金标准**：`run_phase3_evaluation.py` 默认 `--gold-file` 已指向 `gold_labels_k1k7.json`，别手动传旧的（已删除）。
- **别只补库不重跑就报新数字**：幻觉率固化在 raw_outputs 里，不重跑不变。
- **重跑前先备份**：旧 raw_outputs / 旧报告留一份，便于对比新旧幻觉率。
