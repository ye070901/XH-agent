# K1 追问导学章

> 本章对 K1「追问 + 习题批改后端」模块的**两类追问**展开统稿说明：**第一段 = 前置启发式追问**（输入阶段，收窄目标，地基，最高优先）；**第二段 = 后置动态反馈**（输出阶段，答对错→重生成，加分项）。两类追问底层共用同一套对话引导组件，逻辑分开。

---

## 第一段：前置启发式追问

### 1. 逻辑说明

**定位**：前置启发式追问属于**输入阶段**的交互，位于"用户填完信息后、生成资源前"这一环节，是全流程个性化与适配率达标的地基，优先级最高。

**触发时机与目的**：当用户填写的学习目标过宽（例如"我想学机器人"）时，系统无法据此精准定位知识盲区与资源难度。此时系统在**生成之前**主动发起启发式追问，将宽泛目标一步步收窄到具体方向（例如"FANUC 示教器点位编程"），收窄确认后再触发资源生成，从而提升资源与实际需求的适配率与覆盖率。

**底层实现**：对应代码 `backend/src/agents/k1_pre_heuristic_ask.py`。核心逻辑包括：

- `generate_heuristic_questions(context)`：按考试类型与难度上下文生成一组启发式前置问题，每道问题带 `id / text / type / weight` 元数据，覆盖目标确认（`heuristic`）、自评（`self_assessment`）、薄弱主题排序（`topic_prioritization`）与难度为 `hard` 时的经验检查（`experience_check`）等类型。
- `process_pre_ask_response(responses)`：解析用户对前置问题的作答，输出 `topic_confidence`（主题置信度映射）、`overall_confidence`（整体置信度）与 `adaptive_difficulty`（自适应难度，取值收敛于 1.0~10.0），为后续画像与资源生成提供输入。

**"目标过宽"判定方式**：混合式——**规则先行**（关键词数量、目标字数、是否含具体厂商/任务词如 "FANUC / 示教器 / 点位编程" 等硬指标），规则能判则判；规则判不清再调 LLM 辅助判断。符合"轻量判断用规则、复杂判断用 LLM"的分层原则。

**交互流转**：收窄后的目标通过 `state` 传参（`learner_data` 既有机制）交给 Agent1（学情诊断）消费；K1 不直接改 Agent1 内部逻辑。

### 2. 使用场景

- 用户仅给出宽泛表述的学习目标（"我想学机器人""我想学编程"），需要细化到具体方向与任务。
- 用户明确表示想学某个厂商/平台（如 FANUC、KUKA、ABB），但未界定具体环节（如示教器操作、点位编程、离线仿真）。
- 系统需要依据用户自评水平（1-10）与薄弱主题列表，动态调整难度档位后再生成讲义/指南。
- 进阶场景：目标难度为 high 时，追问历史尝试情况，避免重复推送入门内容。

### 3. 交互示例

| 轮次 | 角色 | 内容 |
|------|------|------|
| 1 | 用户 | 我想学机器人操作。 |
| 2 | 系统（K1 追问） | 好的，请问您本次学习的主要目标是？（前置问题 pre_q1） |
| 3 | 用户 | 想掌握工业机器人的示教编程。 |
| 4 | 系统（K1 追问） | 您对示教编程的熟练程度如何，请 1-10 打分？（前置问题 pre_q2，自评） |
| 5 | 系统（K1 追问） | 哪些知识点您最没把握？（前置问题 pre_q3，主题排序） |
| 6 | 用户 | 点位编程相关的运动指令。 |
| 7 | 系统（前端回显收窄目标） | 已为您收窄目标：**FANUC 示教器点位编程**，难度自动定位为"入门偏中级"，即将开始生成针对性学习资源。 |

> 收窄后：目标从"机器人操作"→"FANUC 示教器点位编程"，`learner_data` 携带该目标进入 Agent1 学情诊断，随后触发资源生成。

## 第二段：后置动态反馈

### 1. 逻辑说明

**定位**：后置动态反馈属于**输出阶段**的交互，位于"学习者答题后"环节：依据答题对错触发多智能体协同决策并自动重生成学习内容，同时将批改结果规则化回写画像。它是完整闭环的加分项，资源紧张时可先退化为"批改 + 给建议 + 给 URL"，但保留反馈→重生成的调度入口。

**触发时机与机制**：

- **答错** → 降维解释：定位所答错误的对应知识点，使用更基础、更拆分的讲解与示例重新生成资源。
- **答对** → 进阶挑战任务：基于当前掌握度上探，推送难度更高的进阶任务，维持学习梯度。
- 反馈→重生成依赖 Orchestrator（Arch-L）提供的调度入口，通过 `_retry_hint` 既有机制传递重生成提示。

**底层实现**：对应代码 `backend/src/agents/k1_post_feedback.py`。核心逻辑包括：

- `generate_post_feedback(exam_results, topic_mastery)`：基于批改结果与主题掌握度产出完整反馈报告，包含得分、答题完成率、强项主题（mastery ≥ 80）、弱项主题（mastery < 60）以及推荐建议与整体定级。
- `_derive_recommendations(weak_topics, overall_score)`：按整体得分与弱项主题推导针对性建议（低分触发基础复习建议、给出优先复习主题清单、安排定期练习）。
- `_assess_performance(score)`：将归一化分数映射为 6 档整体评估文案（Excellent / Very Good / Good / Satisfactory / Needs Improvement / Unsatisfactory）。

**画像回写（后置动态反馈的组成部分）**：批改结果按题对错规则化更新 learner 画像，纯规则驱动、不调 LLM：

- **答错** → 对应知识点 `knowledge_map` 掌握度下调 + 置信度上调（获得实测证据）、`skill_gaps.current_level` 修正。
- **答对** → 掌握度上调。
- 回写时更新 `learner_profiles.updated_at`；持久化落在 Opt-4 画像持久化层（SQLite，`data/learner_profiles.db`）。

**习题即时作答链路**：选择题 / 填空题 → 提交 → 批改（填空处理同义/近义，非纯字符串相等）→ 解析 → 学习建议 → 可查资料 URL。

### 2. 使用场景

- 学习者在学习资源后完成前置/练习作答，系统依据对错给出差异化反馈。
- 答题错误：触发降维解释，为薄弱知识点重生成更容易理解的内容。
- 答题正确：触发进阶挑战任务，衔接更高难度梯度。
- 需要将批改证据规则化回写 learner 画像，长期累积形成个性化画像（答错知识点掌握度下调、置信度上调）。
- 填空题存在同义/近义表述时，批改不做纯字符串相等比较，兼顾语义容错。

### 3. 交互示例

| 轮次 | 角色 | 内容 |
|------|------|------|
| 1 | 系统 | 下面是针对"FANUC 点位编程"的 3 道随堂练习，请作答。 |
| 2 | 用户 | 第 1 题选 A，第 2 题填空填"TP 示教器"，第 3 题选 C。 |
| 3 | 系统（K1 批改） | 批改完成：第 1、3 题正确，第 2 题错误（"TP 示教器"与标准答案语义相近但未命中要点：应为 **"FANUC R-30iB 配套 TP 示教器"**）。 |
| 4 | 系统（后置动态反馈·降维） | 检测到您对"示教器型号与配套关系"掌握不足，已为您降维重新生成"示教器基础认知"讲义，重点拆解型号选型与配套关系，并附文档链接。 |
| 5 | 系统（画像回写） | 已更新学习画像：知识点"示教器型号与配套"掌握度下调、置信度上调；整体熟练度趋势将体现在后续推荐中。 |
| 6 | 用户 | （后续练习）全部答对。 |
| 7 | 系统（后置动态反馈·进阶） | 表现优秀，为您推送"点位编程进阶挑战任务"，难度提升一档。 |

> 反馈闭环：答错 → 降维解释 + 画像下调；答对 → 进阶任务 + 画像上调。多智能体协同决策通过 Orchestrator 调度，重生成经 `_retry_hint` 传递。

## 附：与前/后端及依赖的衔接

- **前端（K3）**：提供追问对话 UI 与答题入口。
- **Agent1（学情诊断，diagnosis.py）**：消费收窄后的目标（`learner_data`），K1 不直接改其内部逻辑。
- **Opt-4（画像持久化层 SQLite）**：为画像回写提供落库对象，回写更新 `updated_at`。
- **Orchestrator（Arch-L）**：提供"反馈→重生成"调度入口（`_retry_hint` 机制）。
- **优先级说明**：前置追问（A）为地基，必做优先；后置动态反馈（B）为加分项，资源紧张时优先保 A 砍 B。
