# XH-agent 测试方案规格

> **对应评分**：实用价值 30 分。完整测试方案 = ①专业知识库 ②≥3组学习者画像用例 ③三项指标达标 ④可复现的评测方法。
> **版本**：v1.0
> **更新日期**：2026-08-14
> **负责人**：Opt-4（牵头方法 + 指标计算），K 组（领域内容 + 人工标注），Arch-L（知识点清单汇总）

---

## 一、核心思想（一句话）

测试方案要回答的不是"我们达标了没"，而是"**你凭什么说达标了**"——所以每个指标都必须有一个**客观标准答案**来对照，测出来的数字要有**可复现的流程 + 可信的标定**。

---

## 二、三个真值基准（先建这个，再谈测试）

| 基准 | 是什么 | 对应指标 | 责任人 |
|------|--------|---------|--------|
| **知识库原文** | "原文说啥就是对的" | 幻觉率 | K 组（已有，补 K2） |
| **核心知识点清单** | "工业机器人要会哪些点，分 core/high/standard 三级" | 覆盖率 | K1/K2/K3 各列本领域 → Arch-L 汇总 |
| **学习者画像** | "转岗电工该学初级、本科生该学中级"（每个画像的应得难度/风格） | 适配率 | Opt-4 牵头设计 → K 组补岗位背景 |

> ⚠️ 这三个基准不建，三项指标全是"LLM 自己给自己打分"，评委一眼看穿。

## 三、三项指标测量方法

### 指标1：幻觉率 < 5%

```
幻觉率 = (hallucination + unverifiable) / 总断言数
```

**测量流程**（依赖 K2 的 Agent3 改造）：
1. Agent3 逐句切分生成资源 → 逐句分类
   - 事实断言句 → 比对 KB → `accurate` / `hallucination` / `unverifiable`
   - 非断言句（过渡/修辞/引导）→ `skip`，不比对不删除不计入分母
2. 幻觉率 = (hallucination + unverifiable) / 断言句总数
3. unverifiable → 按 D1 决策从最终资源删除

**关键——"裁判的裁判"（金标准标定）**：
- 人工标注一批断言（≥50 条）的正确答案
- 用金标准**标定 Agent3 的判定准确率**（例：Agent3 判 100 条，人工复核 95 条对 → 判定准确率 95%）
- 测试报告**同时报两个数**：自动测的幻觉率 + 人工标定的判定可信度

### 指标2：适配准确率 ≥ 85%

```
适配率 = (难度匹配 + 风格匹配) / 2
难度匹配：一致=1，差1级=0.5，差2级=0
风格匹配：practice_first 有足够代码示例 / theory_first 有足够理论段落
```

- 每个画像预先定好"应得难度 + 学习风格"标准答案
- 比对生成资源的实际难度/风格，算匹配度
- 同样需人工抽检标定（难度/风格判定不能全信 LLM）

### 指标3：覆盖率 ≥ 90%

```
覆盖率 = 被覆盖的 core/high 盲区 / 总 core/high 盲区
```

- 输入 = 画像的 skill_gaps（critical/high 盲区）+ 核心知识点清单
- 看生成资源覆盖了多少 critical/high 盲区
- 依赖核心知识点清单（Arch-L + K 组先建）

## 四、测试用例设计（≥50 组）

### 4.1 用笛卡尔积撑数量，不硬凑

```
用例 = 学习者画像 × 知识点 × 资源形态
建议：3~5 画像 × 12~15 知识点 = 36~75 组
     + 3~5 负样本
     ≈ 50+ 组
```

### 4.2 画像设计（≥3 组，差异化背景）

| 画像 | 背景 | 应得难度 | 学习风格 |
|------|------|---------|---------|
| A 转岗电工 | 有电气基础，没摸过机器人 | 初级 | practice_first（重实操） |
| B 自动化本科生 | 学过运动学，缺一线调试 | 中级 | theory_first（重理论） |
| C 老技师 | 干过示教，想学离线仿真 | 进阶 | practice_first |

> 画像由 Opt-4 牵头设计框架，K 组补工业机器人真实岗位背景，确保"贴合行业实际岗位需求"（评分原文）。

### 4.3 负样本（加分项，证明防幻觉是真实的）

故意构造"知识库没覆盖"的用例，验证系统能**正确标 unverifiable 并删除**，而不是硬编一个幻觉。例：输入"要学 FANUC 离线仿真"但 K2 内容空 → 系统应标无权威参考，不硬编。

## 五、交付物清单（最终测试报告应含）

1. 测试范围与目标（对标三项指标）
2. 测试环境（数据、模型、参数）
3. 三个真值基准说明（怎么来的、谁定的）
4. 测试用例全集（≥50 组，含画像定义 + 预期结果）
5. 三项指标测量结果 + 金标准标定报告
6. 失败用例分析（哪些没过、为什么、怎么改）
7. 领域泛化说明（换知识库即可迁移的证据 → 命中"可迁移性"评分）

## 六、责任分工与依赖

| 环节 | 责任人 | 依赖 |
|------|--------|------|
| 核心知识点清单 | K1/K2/K3 各列 → Arch-L 汇总 | 无（先做） |
| 学习者画像设计 | Opt-4 牵头 + K 组补背景 | 无（可并行） |
| 金标准标注 | K 组标注 + Opt-4 出规范 | Agent3 改造后 |
| 三项指标计算 `metrics.py` | Opt-4 | 知识点清单 + 画像 + Agent3 三态输出 |
| 测试用例全集 | Opt-4 + 新人(人8)整理 | 画像 + 知识点清单 |

---

## 七、执行顺序（关键路径）

```
1. Arch-L + K组：核心知识点清单（先做，卡覆盖率）
2. Opt-4 + K组：学习者画像（并行）
3. K2：Agent3 改造（逐句比对三态输出，卡幻觉率测量）
4. K组：金标准标注（Agent3 改造后，标定判定准确率）
5. Opt-4：metrics.py 三项指标计算（前四步都就绪后）
6. Opt-4 + 人8：50 组用例跑测 + 出报告
```

> **最高优先**：核心知识点清单（Arch-L + K 组）——它现在完全空白，且是覆盖率≥90% 的唯一裁判。
