# MVP 分工安排（8 人全员参与版）

> **目标：** Agent 1 + Agent 2 闭环，前后端可跑，七月底验收。8 人全部参与。
> **知识来源：** LLM 自身知识（不做本地文档检索）。
> **原则：** 每个模块两个人，一个人主写，一个人 review，互相 backup。
>
> **📋 每个人的具体操作步骤见：** [`docs/MVP_TASKS.md`](./MVP_TASKS.md) — 每人一份，每一步都写出来了。

## 三、5 条工作线 + 人员配对

### 线 1: 后端核心（角色1 + 角色2）

| 文件 | 角色1（主） | 角色2（副） |
|------|----------|----------|
| `backend/src/graph/orchestrator.py` | ✅ 主写 | Review |
| `backend/src/api/main.py` | ✅ 主写 | 对接测试 |
| `start.bat` | ✅ 主写 | 测试 |

**角色1 要做什么：**
- 简化 orchestrator 为 diagnose → generate 两步
- API 接收 JSON，返回 diagnosis + resources
- 写 start.bat 启动脚本
- 负责 dev 分支合并

**角色2 辅助什么：**
- 角色1 写完后第一个跑起来测试
- 发现 API 返回格式不对 → 告诉角色1 修
- 确认 start.bat 在 Windows 上能双击运行

---

### 线 2: LLM 层（角色2 + 角色6）

| 文件 | 角色2（主） | 角色6（副） |
|------|----------|----------|
| `backend/src/llm/client.py` | ✅ 主写 | Review + 测试 |

**角色2 要做什么：**
- 加演示模式：无 API Key 时返回模拟数据
- 模拟数据根据 prompt 内容自动区分（诊断/生成）
- 配 Key 时走真实 LLM 调用

**角色6 辅助什么：**
- 测试角色2 的代码：不配 Key 跑 5 次，配 Key 跑 5 次
- 确认模拟数据格式和真实返回格式一致
- 记录两种模式的差异，给角色2 反馈

---

### 线 3: 两个 Agent（角色4 + 角色5）

| 文件 | 角色4（Agent 1 主） | 角色5（Agent 2 主） |
|------|-------------------|-------------------|
| `backend/src/agents/diagnosis.py` | ✅ 主写 prompt | 测试诊断效果 |
| `backend/src/agents/generation.py` | 测试生成效果 | ✅ 主写 prompt |

**角色4 要做什么：**
- 精调 Agent 1 的 system prompt，让诊断更准
- 确保输出不是"初级/中级/高级"三分法，而是细粒度知识缺口
- 构造 5 组不同学习者输入，验证诊断结果真的不同

**角色5 要做什么：**
- 重构 Agent 2 的 system prompt，去掉 KB 约束
- 让 LLM 用自己的知识生成，但根据 skill_gaps 个性化
- 确保不同难度和学习风格真的影响生成内容

**两人怎么配合：**
- 角色4 把诊断结果给角色5 → 角色5 用来调 Agent 2
- 角色5 生成的内容给角色4 → 角色4 用来验证 Agent 1 的诊断是否准确
- 每天花 15 分钟对一下："你给我的输出，我生成了 X，你觉得合理吗？"

---

### 线 4: 测试 + Phase 2 方案（角色6 + 角色7）

| 产出 | 角色6（主） | 角色7（副） |
|------|----------|----------|
| MVP 测试用例 | ✅ 设计 | 执行测试 |
| MVP 测试报告 | 执行测试 | ✅ 撰写 |
| Phase 2 辩论协议方案 | ✅ 设计 | 补充 |
| Phase 2 评估指标方案 | 补充 | ✅ 设计 |

**角色6 要做什么：**
- 设计 MVP 测试：至少 5 组输入 × 3 种资源类型
- 搭建测试框架：一个脚本可以批量调 `/api/generate`，记录结果
- 设计 Phase 2 辩论协议方案（基于现有 `debate/engine.py`）

**角色7 要做什么：**
- 执行角色6 的测试用例，记录问题
- 写测试报告（哪些输入效果差，为什么差）
- 设计 Phase 2 的三项指标评估方案

**两人怎么配合：**
- 角色6 写测试脚本 → 角色7 跑 → 角色7 汇总问题 → 角色6 分析根因
- Phase 2 的辩论方案二人一起讨论，各写自己擅长的一半
