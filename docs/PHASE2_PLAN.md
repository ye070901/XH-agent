## 二、架构总览

```
用户输入 → 闸门1(特异性检测) → Agent1(学情诊断) → 闸门2(诊断质量)
  → Agent2 Step1(生成检索Query) → RAG检索 → 闸门3(召回质量)
  → Agent2 Step2(基于KB约束生成) → Agent3(事实核查) → 博弈引擎(辩论)
  → Agent4(保真修正) → Agent3再审 → 标准化输出 → 前端
```

### 2.1 4 Agent + 1 博弈引擎

| Agent | 评分标准对应 | 核心职责 |
|-------|------------|---------|
| Agent 1 学情诊断 | "学情画像构建" | 知识掌握度评估 + 盲区识别 + 学习风格判定 |
| Agent 2 知识生成 | "领域知识个性化生成" | 拆解检索query + 基于KB约束生成讲义/指南/测验 |
| Agent 3 内容审核 | "内容审核" | 事实断言逐条提取 + 原文比对 + FactCheckResult |
| Agent 4 保真修正 | "校验-决策协同闭环" | 逐条修正错误 + 补溯源 + 冲突并列 |
| 博弈引擎 | "辩论与交叉验证" | Agent 3(质疑) ↔ Agent 2/4(应诉) 3轮对抗 |

### 2.2 六道防幻觉防线

| 防线 | 环节 | 卡什么 | 谁执行 |
|------|------|--------|--------|
| ① | 检索约束 | 相似度 < 0.6 不进 context，KB 没有的不硬编 | RAG 工具层 |
| ② | 约束生成 | 只能基于 KB 原文，每条断言标注来源 | Agent 2 (prompt) |
| ③ | 事实核查 | 逐条断言 vs 原文，标 accurate / hallucination / unverifiable | Agent 3 |
| ④ | 博弈对抗 | 质疑 → 应诉 → 双方援引原文 → 裁决 | 博弈引擎 |
| ⑤ | 保真修正 | 删除错误、补溯源、冲突并列不选边 | Agent 4 |
| ⑥ | 标准化包装 | 溯源 + 审核 + 辩论记录全部下发，透明可查 | 编排器 |

### 2.3 三道质量闸门

| 闸门 | 位置 | 校验什么 | 不通过行为 |
|------|------|---------|-----------|
| 闸门1 | 用户提交后 | 学习目标是否具体（长度、关键词、方向明确性） | 追问用户补充 |
| 闸门2 | Agent 1 输出后 | skill_gaps 的 topic 是否足够精细 | 退回重诊 |
| 闸门3 | RAG 检索后 | 召回覆盖率、相似度、内容总量 | 降级处理+标注缺失 |

1. RAG 系统设计与实现

**数据规模**：4子领域 × 8篇 × 2000-5000字 = 32篇，~96,000字，ChromaDB ~200+ chunks

**来源分级**：S级(官方文档)直接入库 / A级(权威教程)交叉审核 / B级(论文/博客)对照S级验证 / C级(社区内容)原则上不入库

## 五、技术决策记录

1. **检索 Query 由 Agent 2 生成**，不由编排器机械拼接——生成内容的人最清楚需要什么素材
2. **"检索专家"降级为 RAG 工具函数**，不是 Agent——不需要 LLM 推理
3. **"统筹决策"是编排器代码逻辑**，不是 Agent——纯 if-else + 配置读取
4. **Agent 命名直接对应评分标准**：学情诊断、知识生成、内容审核、保真修正
5. **知识库是裁判**：双方争议时以 KB 原文为准
6. **博弈只辩事实，不辩风格**：难度匹配/风格适配不进辩论
7. **降级不是拒绝**：KB 覆盖不足时标注缺失后继续生成

## 六、评分标准覆盖

| 维度 | 分值 | 覆盖方式 |
|------|------|---------|
| 作品完整性 | 30 | 4 Agent + 3 闸门 + 编排器 → "学情→生成→校验→决策→反馈"全流程闭环 |
| 技术创新性 | 25 | 辩论引擎 + 6道防幻觉防线 + 知识库约束生成 + 高保真溯源 |
| 用户体验 | 15 | Agent 协同拓扑图 + 辩论 timeline + 知识雷达图 + 学习路径 DAG |
| 实用价值 | 30 | 三项硬指标自动评估(幻觉率<5%/适配率≥85%/覆盖率≥90%) + 4领域知识库 |
