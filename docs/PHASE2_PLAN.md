### 2.3 基础流水线（全文统一）

用户输入（工业机器人调试相关问题）
  → InputGate（闸门1：输入校验 / 敏感过滤 / 意图识别）
    → Agent1 学情诊断（识别用户技能水平、薄弱环节）
      → DiagnosisGate（闸门2：诊断结果合理性检查 / 置信度阈值）
        → Agent2 生成检索 Query
          → RAG 检索（工业机器人知识库）
            → RecallGate（闸门3：召回质量把关，裁决路径 PASS / RETRY / FALLBACK）
              → Agent2 基于知识库生成回答
                → Agent3 初审（逐项核验操作准确性）
                  → Agent4 保真修正（事实核查 + 厂商手册引用校准）
                    → Agent3 再审 → 标准化输出（操作步骤 + 安全提示 + 引用来源）

### 2.4 三闸门裁决路径定义

| 闸门 | 位置 | PASS | RETRY | FALLBACK |
|------|------|------|-------|----------|
| InputGate | 用户输入后 | 校验通过，进入 Agent1 | N/A（前端拦截） | 返回输入引导提示 |
| DiagnosisGate | Agent1 输出后 | 诊断结果合理，进入 Query 生成 | 补充诊断信息后重试（最多 2 次） | 降级为基础诊断模板 |
| RecallGate | RAG 检索后 | 召回满足阈值，进入生成 | 改写 Query 重检（最多 3 次） | 无知识库模式 / 提示无法回答 |

> 三闸门覆盖输入、诊断、召回三个关键节点。末端「标准化输出」步骤自带格式校验与合规检查，不再独立成闸门。

└────────────┴──────────────────────────────────────┴───────────────────────────────────────────┘

- 抽检通过率 ≥90% → 当日批次全部入库 data/reviewed/
- 抽检通过率 <90% → 整批退回，返工后重新走 Step 3→4

▎ MVKB 累计目标按 90% 通过率保守估算：K1+K2+K3 日均提交约 50~65 篇 × 90% ≈ 45~58 篇/日。Day 2 ≥45 篇 → Day 3 ≥95 篇 → Day 4 ≥150 篇 → Day 5 ≥205 篇（达标 200）。若中位 18+18+24=60 篇/日，Day 4 末即达标 216×90%≈194，Day 5 稳超。

不是审技术深度——审三样：
1. 格式对不对（标题有#、有来源URL、有日期、有摘要）
2. 内容能不能用（正文 ≥500 字、含操作步骤或代码）
3. 分类对不对（data/ vs docs/reference/）
▎ "FANUC 的 PTP 指令参数写对了没有"——不用你判断，K1 互审会看。

每天抽检时顺手标记权威等级，算 A+B 占比：
- ≥80% → PASS
- ＜80% → 整批退回，附"哪些是 C 级、应该找什么源头替换"
