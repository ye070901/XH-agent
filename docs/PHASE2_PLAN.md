## 一、架构总览

```
用户输入 → 闸门1(特异性检测) → Agent1(学情诊断) → 闸门2(诊断质量)
  → Agent2 Step1(生成检索Query) → RAG检索 → 闸门3(召回质量)
  → Agent2 Step2(基于KB约束生成) → Agent3(内容审核) → 博弈引擎(辩论)
  → Agent4(保真修正) → Agent3再审 → 标准化输出 → 前端
```

### 1.1 4 Agent + 1 博弈引擎

| Agent | 评分标准对应 | 核心职责 |
|-------|------------|---------|
| Agent 1 学情诊断 | "学情画像构建" | 知识掌握度评估 + 盲区识别 + 学习风格判定 |
| Agent 2 知识生成 | "领域知识个性化生成" | 拆解检索 query + 基于 KB 约束生成讲义/指南/测验 |
| Agent 3 内容审核 | "内容审核" | 事实断言逐条提取 + 比对校验 + 输出 FactCheckResult |
| Agent 4 保真修正 | "校验-决策协同闭环" | 逐条修正错误 + 补溯源 + 冲突并列 |
| 博弈引擎 | "辩论与交叉验证" | Agent 3(质疑) ↔ Agent 2/4(应诉) 3 轮对抗 |

### 1.2 三道质量闸门

| 闸门 | 位置 | 校验什么 | 不通过行为 |
|------|------|---------|-----------|
| 闸门1 | 用户提交后 | 学习目标是否具体 | 追问用户补充 |
| 闸门2 | Agent 1 输出后 | skill_gaps topic 是否足够精细 | 退回重诊 |
| 闸门3 | RAG 检索后 | 召回覆盖率、相似度、内容总量 | 降级处理+标注缺失 |

## 二、防幻觉体系

### 2.1 有知识库时（六道防线）

| 防线 | 环节 | 卡什么 | 谁执行 |
|------|------|--------|--------|
| ① 检索约束 | RAG 检索 | 相似度 < 0.6 不进 context | RAG 工具层 |
| ② 约束生成 | Agent 2 生成 | 只能基于 KB 原文，每条断言标注来源 | Agent 2 (prompt) |
| ③ 事实核查 | Agent 3 审核 | 逐条断言 vs 原文，标 accurate / hallucination / unverifiable | Agent 3 |
| ④ 博弈对抗 | 辩论引擎 | 质疑 → 应诉 → 援引原文 → 裁决 | 辩论引擎 |
| ⑤ 保真修正 | Agent 4 修正 | 删除错误 + 补溯源 + 冲突并列 | Agent 4 |
| ⑥ 标准化包装 | 编排器 | 溯源+审核+辩论记录全部下发，透明可查 | 编排器 |

### 2.2 脱离知识库时（三道防线）

当用户的学习目标超出 KB 覆盖范围、或 KB 尚未建好时，没有知识库原文作为"真理基准"，改用以下策略：

| 防线 | 环节 | 策略 |
|------|------|------|
| ① 生成自我约束 | Agent 2 生成 | 每条技术断言标注置信度(高/中/低)；不确定的 API 行为标注[建议运行验证]；代码示例标注[已测试/未测试] |
| ② 内部一致性检查 | Agent 3 审核 | 不做原文比对，改为检查：概念前后矛盾、API 名称写法不一致、代码缺少 import、步骤跳跃缺失。输出 ConsistencyReport |
| ③ 用户反馈闭环 | 前端 + 编排器 | 每份资源附带反馈入口。用户标"有误"→Agent 4 修正。多次反馈积累为 KB 候选内容 |

**何时触发有/无 KB 模式的切换**：闸门3 检测到所有检索 query 的相似度均 < 0.6 → 标记 `downgrade_mode` → Agent 3 自动切换为一致性检查模式。

## 五、为什么用 WebSocket

评分标准要求"多智能体协同调度过程与决策逻辑可视化交互流畅"。不使用 WebSocket 的后果：一次生成耗时 60-120 秒，前端只能看到转圈，完全感知不到 Agent 间的协作过程。

WebSocket 让编排器在每个关键节点（Agent 开始/完成、闸门拦截、辩论轮次）实时推送状态变更。前端 Agent 拓扑图上节点颜色随状态变化（思考中→黄色、执行完成→蓝色、错误→红色），辩论 timeline 实时弹出攻防条目。

数据流：编排器执行 Agent → `broadcast_agent_event()` → WebSocket → 前端更新 DOM。一次连接，零次多余 HTTP 请求。

## 六、技术决策记录

1. **检索 Query 由 Agent 2 生成**，不由编排器机械拼接
2. **"检索专家"降级为 RAG 工具函数**，不是 Agent
3. **"统筹决策"是编排器代码逻辑**，不是 Agent
4. **Agent 命名直接对应评分标准**：学情诊断、知识生成、内容审核、保真修正
5. **知识库是裁判**：有 KB 时双方争议以 KB 原文为准
6. **无 KB 时 Agent 3 切换为一致性检查**：不装"我知道对错"，只检查自相矛盾
7. **博弈只辩事实，不辩风格**：难度匹配不进辩论
8. **降级不是拒绝**：KB 不足时标注缺失后继续生成
