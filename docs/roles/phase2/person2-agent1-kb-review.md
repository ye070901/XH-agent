# 人员2 — Agent 1 学情诊断 + 知识库交叉审核

## 角色定位

学情诊断负责人 + 知识库质量守门人。Agent 1 是流水线的入口，输出质量决定下游所有环节的上限。

## 依赖关系

```
被谁依赖：全体 → Agent 1 的诊断结果是 Agent 2/3/4 的输入
         人员8 → 知识库文档需要你审核后才能入库

依赖谁：人员1 → 编排器规定了 Agent 1 的 process() 签名
        人员8 → 知识库文档初稿
```

## 第一阶段：7/27 — 8/1（6天）

### 任务 1.1：Agent 1 Prompt 精度升级（3天）

**文件**：`backend/src/agents/diagnosis.py`（改造现有文件）

升级SYSTEM_PROMPT增加精度约束：
- 盲区必须拆解到具体技术点级别，禁止宽泛命名（❌"AI基础" → ✅"Transformer自注意力机制"）
- 盲区命名格式："{具体技术} - {子方向}"（如"LangGraph - 条件路由与动态分支"）
- 至少5个知识点，每个含 level/confidence/evidence/priority
- priority=critical的盲区必须是"不掌握就无法推进学习"的前置依赖

### 任务 1.2：闸门2 协作 — 支持退回重诊（1天）

在Agent 1的prompt中处理`state["diagnosis_retry_hints"]`：如果编排器退回重诊，prompt追加"上一轮诊断的以下宽泛topic请拆解为更具体的技术点"。

### 任务 1.3：知识库审核标准制定（2天）

**文件**：`docs/KB_REVIEW_STANDARD.md`（新建）

审核checklist：API签名正确性(逐条对照官方文档) / 概念定义准确性(≥2个S级来源交叉验证) / 代码示例可运行性 / 版本时效性 / 来源标注。

**交付物**：`diagnosis.py` 升级版 + `KB_REVIEW_STANDARD.md`

## 第二阶段：8/3 — 8/10（8天）

### 任务 2.1：知识库交叉审核（5天）

人员8的32篇文档由你逐篇审核。约12-16小时。流程：通读→API断言查官方文档→代码示例确认可运行→审核通过标注reviewer→不通过退回人员8。

### 任务 2.2：Agent 1 最终调优（3天）

用审核通过的KB文档测试Agent 1：检查skill_gaps是否与KB术语一致→调整few-shot示例→调temperature（0.2不够稳则降0.1）→3组差异化输入全链路测试。

**交付物**：Agent 1最终版 + 3组测试用例的诊断结果

## 第三阶段：8/10 — 8/19（10天）

- 8/10-8/12：联调（Agent 1 接入编排器 + 闸门2退回重诊验证）

- 8/15-8/19：准备3组测试用例（用例1:计算机本科+Python1年→学LangGraph / 用例2:零基础→了解AI Agent / 用例3:算法工程师→深入多Agent协同）

## 验收标准

- [ ] Agent 1 输出的 skill_gaps 所有 topic 长度 ≥ 6 字
- [ ] 不含"基础"/"入门"/"进阶"等泛化词
- [ ] 3组不同输入产生3份结构相同内容不同的诊断
- [ ] 退回重诊后第二次输出的 topic 明显更细粒度
- [ ] KB审核完成率 ≥ 80%（32篇中至少26篇通过）
- [ ] 3组测试用例已打包为JSON
