## 二、关键决策（本阶段新增）

| # | 决策 | 说明 |
|---|------|------|
| D1 | **无权威参考 = 删除** | 幻觉率公式 = (hallucination + unverifiable)/total，unverifiable 计入分子；仅标注保留会拉爆幻觉率。无 KB 支撑的断言从最终资源删除，不计入核心知识点 |
| D2 | **博弈引擎三态裁决** | 每个争议断言查 KB：①支持Agent2→保持原文+标来源；②支持Agent3→Agent2撤回/用原文替换；③未覆盖→删除（同D1） |
| D3 | **权威等级加权** | A 级一手原文 > B 级二手；冲突以更高权威等级为准 |
| D4 | **博弈终止边界** | 每资源最多 3 轮，每轮最多 N=3~5 个争议断言；裁决纯代码规则，不调 LLM（防第二层幻觉） |
| D5 | **Agent3 改造前置** | audit.py 先改造成"提取事实断言→KB逐条比对→三态输出"，再写 debate 引擎；否则辩论退化为两个 LLM 互相拍脑袋 |
| D6 | **资源溯源双层** | ①内部：Agent3 核验；②前端：用户可见"结论+可折叠KB原文"。命中"高保真溯源"创新点 + 用户体验 15 分 |
| D7 | **文档视频横切分摊** | 文档由各模块作者边做边写（作者最懂），人8 搭框架+统稿；视频冻结后 3 人集中（录屏 K3 + 旁白待定 + 剪辑人8） |
| D8 | **交互反馈→动态决策更新闭环** | 答题对错作为反馈信号，触发多智能体协同决策自动重生成：答错→降维解释、答对→进阶挑战任务。补齐"作品完整性30分"要求的最后两个环节 |
| D9 | **两类追问拆清** | 前置启发式追问（输入阶段收窄目标，地基，必做优先）+ 后置动态反馈（输出阶段答对错→重生成，加分项）。底层共用对话组件，逻辑分开 |

## 2.1 全流程闭环（对应评分"作品完整性 30 分"）

```
学情画像构建 → 多智能体协同调度（诊断/生成/审核）→ 领域知识个性化生成
        ↑                                                      │
        │                                                      ↓
  动态决策更新 ←── 交互反馈（答题对错/追问）←── 学习者使用资源
   （降维重讲 / 进阶挑战）                        （作答 / 阅读 / 追问）
```

- **交互反馈**：习题作答提交（对错）、追问内容、浏览行为 → 作为反馈信号回传。
- **动态决策更新**：多智能体据反馈重新决策 → 答错生成"降维解释"、答对生成"进阶挑战任务"、追问暴露新盲区则更新资源。
- **落点**：K1（后端批改+触发重生成）+ Arch-L（编排调度入口）+ K3（前端答题入口）。见 4.5。

### 4.1 Arch-L — 编排器接入 + 核心知识点清单

**文件**：`backend/src/graph/orchestrator.py`（接入）+ `data/core_knowledge_map.json`（新建）

| 任务 | 交付标准 |
|------|----------|
| 博弈引擎接入流水线 | Agent3 输出三态断言 → 争议断言进 debate 引擎 → 裁决结果回写资源，全链路可跑通 |

| 文档：Gates/Scheduler/部署章 | 段2 统稿 |

**依赖**：K2 的 audit.py 改造完成 → 才能接 debate 引擎。

### 4.2 Opt-2 — 博弈引擎

**文件**：`backend/src/debate/engine.py`（新建）+ `backend/src/debate/rules.py`（裁决规则，纯代码）

| 任务 | 交付标准 |
|------|----------|
| 三态裁决规则 | 每个争议断言查 KB → 支持A2/支持A3/未覆盖 三态，未覆盖→删除 |
| 权威等级加权 | A>B，冲突取高权威 |
| 终止边界 | 每资源 3 轮、每轮 N=3~5 断言，超限直接收口 |
| 辩论→下一问题衔接 | 一问题裁决闭环 → 自动转下一争议问题，全清空→资源辩论结束 |
| 单元测试 | 覆盖三态裁决 + 权威加权 + 终止边界 |

**依赖**：K2 的 audit.py 三态输出（上游，串行）。裁决不调 LLM。

### 4.3 Opt-3 — Agent4 保真修正 + 资源溯源

**文件**：`backend/src/agents/agent4.py`、`backend/src/agents/correction.py`（改造）

| 任务 | 交付标准 |
|------|----------|
| Agent4 保真修正 | 对辩论裁决后的资源做事实校准：落实删除项、把 KB 原文替换拼接回语境 |
| 资源溯源绑定 | 讲义/指南每个事实点 = "生成陈述 + KB 原文出处" 绑定输出 |
| 无 KB 模式 | downgrade_mode=True → 一致性检查（前后矛盾/术语不一致/缺import/步骤跳跃） |

**依赖**：Opt-2 的辩论裁决结果（下游消费）。

### 4.4 Opt-4 — 测试方案 + 三项指标

**文件**：`backend/src/evaluation/metrics.py`（新建，当前空目录）

| 任务 | 交付标准 |
|------|----------|
| 三项指标计算 | 幻觉率 = (hallucination+unverifiable)/total <5%；适配率 = 难度+风格 ≥85%；覆盖率 = 覆盖的core/high盲区/总盲区 ≥90% |
| 学习者画像设计（牵头） | ≥3 组差异化画像 + 每个画像的应得难度/风格标准答案；K组补岗位背景 |
| 金标准标注规范 | 出标注规范 + 数据格式，K组执行人工标注，标定 Agent3 判定准确率 |
| 测试用例 ≥50 组 | ≥3 画像 × ~12 知识点笛卡尔积 + 3~5 负样本（故意测幻觉/适配失败） |
| 测试数据打包 | 至少 1 个垂直领域知识库切片 + ≥2 组差异化学习者画像完整输入输出 |
| 文档：API+测试方案章 | 段2 统稿 |

**依赖**：Arch-L 的核心知识点清单（覆盖率基准）、K 组的 QA 数据集。

### 4.5 K1 — 追问（前置收窄 + 后置反馈）+ 习题批改后端

**文件**：`backend/src/agents/` 新增追问逻辑 + 批改逻辑

> **两类"追问"拆清**：①前置启发式追问（输入阶段，收窄目标，地基，最高优先）；②后置动态反馈（输出阶段，答对错→重生成，加分项）。底层共用同一套对话引导组件，逻辑分开。

| 任务 | 交付标准 |
|------|----------|
| **前置启发式追问（A，最高优先）** | 用户填完信息后、生成前，判断学习目标是否过宽（如"我想学机器人"）→ 追问细化到具体方向（如"FANUC 示教器点位编程"）→ 收窄后触发资源生成。命中创新性"动态追问与启发式交互导学" |
| **后置动态反馈（B，加分项）** | 答题对错 → 触发多智能体协同决策 → 自动重生成（答错→降维解释 / 答对→进阶挑战任务）。命中完整性"交互反馈→动态决策更新" |
| 习题即时作答 | 选择题/填空题 → 提交 → 批改（填空处理同义/近义，非纯字符串相等）→ 解析 → 学习建议 → 可查资料 URL |
| K1 知识库填充 | 持续录入基础操作/示教编程资料 |
| 文档：追问导学章 | 段2 统稿 |

**追问"目标过宽"判定方式（已定）**：混合式——**规则先行**（关键词数、目标字数、是否含具体厂商/任务词如"FANUC/示教器/点位编程"等硬指标），规则能判则判；规则判不清再调 LLM 辅助判断。符合"轻量判断用规则、复杂判断用 LLM"的分层原则。

**依赖**：前置追问需 Agent1（学情诊断）承接收窄后的目标；后置动态反馈需 Orchestrator（Arch-L）提供"反馈→重生成"调度入口；前端（K3）提供追问对话 UI + 答题入口。

> **优先级说明**：前置追问（A）是"个性化"的地基，直接决定适配率/覆盖率能否达标，必做优先；后置动态反馈（B）可先退化为"批改+给建议+给URL"，资源紧张时砍 B。
