## 四、MVP 验收清单（7/30 逐条检查）

| # | 验收项 | 标准 |
|---|--------|------|
| 1 | `start.bat` 或手动启动能运行 | 后端 + 前端都启动，不报错 |
| 2 | 不配 API Key 能走完 | 演示模式生效，返回的不是 `{}` |
| 3 | 配 API Key 也能走完 | 返回真实 LLM 生成的内容 |
| 4 | 前端页面正常显示 | 浏览器 http://localhost:8501 无白屏 |
| 5 | 学情诊断有内容 | 包含学习风格、推荐难度、≥3 个知识盲区 |
| 6 | 学习资源有内容 | 至少 1 份（讲义/指南/测试题），Markdown 正常渲染 |
| 7 | 不同输入产生不同结果 | 换学历/学习目标 → 诊断真的不同 |
| 8 | `/health` 显示知识库 | `kb_docs` > 0 |
| 9 | 三种资源类型可选 | lecture / guide / quiz 分别能生成 |
| 10 | 错误提示友好 | 后端没启动时前端不白屏，提示"请先启动后端" |

## 六、关键提醒

1. **仓库里已有参考代码** — 团队工作是理解+验证+调整，不是从零写。遇到看不懂的地方，把代码贴给 AI 问"这段在做什么"。
2. **7/16 晚上的全员会议是最重要的一件事** — 不开这个会，后面两周全乱。
3. **7/19-20 周末不强制加班** — 角色1 最忙（整合），角色3 其次（审文档），其他人量力而行。
4. **7/23 全员联调** — 这一天每个人都必须在，至少花 2 小时测系统。
5. **角色4-7 在 MVP 期间的核心工作是理解系统，不是写代码。** Phase 2 才是他们发力的时候。
6. **就算配了 API Key，也先测一遍演示模式** — 确保不依赖外部服务也能演示。
7. **7/31 之前只做 MVP——不加新功能，不优化 prompt，不做 Agent 3。**
