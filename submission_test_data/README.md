## 样例选取说明（为什么是 D / I / K）

从 10 组画像中挑 3 组「差异最大化」的，覆盖题目要求的不同背景适配能力：

- **画像 D（零基础转行）**：餐饮门店店员、市场营销、前置测试 5/120 → 代表「从零起步」，验证系统对行业外学习者的适配。
- **画像 I（熟练工程师）**：自动化本科、6 年调试、88/120 → 代表「高手进阶」，验证系统对熟练从业者的适配。
- **画像 K（过度自信）**：自称「十年专家、要最高级内容」，但前置测试仅 20/120 → 代表「对抗样本」，验证系统能否用**客观测试证据压制自述**（防过度自信适配）。

> 完整 10 组画像（D–M，含纯零基础 / 仅听过 / 理论型 / 实操型 / 均衡 / 熟练 / 权威 / 过度自信 / 知识空白 / 自相矛盾）见 `02_学习者画像/learner_profiles.json`。

## 复现方法

三组样例是真实调用生产后端生成的（非手写假数据），可用仓库自带脚本重跑：

```bash
# 1. 启动后端（演示模式或真实模式均可，取决于 .env 的 LLM_API_KEY）
cd XH-agent && python main.py

# 2. 重新生成 D/I/K 三组端到端输出（读 learner_profiles.json，调 /api/generate）
python submission_test_data/_build/generate_samples.py

# 3. 从原始 JSON 重新拆出本测试数据包（切片复制 + 样例拆分）
python submission_test_data/_build/build_package.py
```

生成的原始完整响应（含 `task_id / diagnosis / resources / audit / agent_log`）保存在 `_build/raw_samples.json`。

## 与评分指标的对账

题目「实用价值 30 分」要求三项硬指标（幻觉率 <5% / 适配率 ≥85% / 覆盖率 ≥90%），并配套完整测试方案。本包是**测试数据**，其对应的**真值基准**与**测量结果**另见仓库：

- 核心知识点清单（覆盖率裁判）：`data/core_knowledge_map.json`
- 学习者画像真值（适配率裁判）：`data/evaluation/learner_profiles.json`
- 金标准标注（幻觉率裁判标定）：`data/evaluation/gold_labels.json`
- 评测报告：`data/evaluation/runs/phase3_report.json`

### 三组样例「预期 vs 实测」一览（如实记录）

| 画像 | 预期难度 | 实测难度 | 预期风格 | 实测风格 | 说明 |
|------|:---:|:---:|:---:|:---:|------|
| D 零基础转行 | beginner | beginner | visual | visual | 难度、风格全对齐 |
| I 熟练工程师 | advanced | advanced | practice_first | practice_first | 难度、风格全对齐 |
| K 过度自信 | beginner | beginner | practice_first | practice_first | **对抗样本通过**：客观测试证据压制了「10 年经验」自述 |

> 三组难度全部对齐真值（含刻意构造的对抗样本 K）。这是通过学情诊断 Agent 的「客观证据校正」实现的：前置测试得分率直接决定难度档位（<30%→beginner、<65%→intermediate、≥65%→advanced），使 20/120 的自述专家被正确压回 beginner、88/120 的熟练工程师被正确提回 advanced。
>
> 当前 D/I/K 三组样例的难度与学习风格均与对应画像真值一致。每次重跑后，
> 应以 `04_测试执行记录/test_manifest.json` 和各用例记录中的原始响应哈希为准，
> 不应手工修改汇总结论。
