## 正文

### 1. DCP 与循环 I/O 不是同一层问题

DCP（Discovery and Configuration Protocol）用于发现设备、识别设备以及设置/读取 PROFINET 站名等启动配置。PROFINET IO 设备通常由**站名**被控制器识别，IP 配置、站名、GSDML、模块配置和过程数据长度必须对应同一工程版本。

循环 I/O 则在建立通信关系后按配置周期交换过程数据。PI 的系统说明指出，消费者会监视循环数据是否在配置的监视时间内到达；逾期会向应用报告故障。因此，能扫描到设备、能 ping 通设备或能通过 DCP 重命名，都不能单独证明循环过程数据已正确建立。

### 2. 字节序和数据布局的边界

PROFINET 只运输字节序列；16/32 位数值如何解释取决于 PLC、机器人或设备的具体 GSDML、设备手册及程序映射。不得把“PROFINET 一律大端（Big-Endian）”作为跨设备结论。调试时应对照接口表逐项确认：起始字节、位号、数据类型、长度、符号位、缩放、字顺序和字节顺序。

建议先用一个已知的单 bit 或固定 16 位测试值验证映射，再恢复工艺数据。发现数值成倍、符号反转或高低字颠倒时，先检查数据类型和字序定义，不要通过在业务程序中随意交换字节来掩盖工程不一致。

### 3. 推荐诊断顺序

1. 记录 PLC 工程版本、设备站名、MAC、IP、GSDML 版本及模块/子模块的实际字节长度。
2. 使用工程工具或 DCP 扫描确认目标 MAC 对应的设备和站名，排除重复站名、重复 IP 与误连设备。
3. 在线对比已组态模块顺序、输入/输出长度、槽位和报警诊断；过程映像长度必须与设备端一致。
4. 检查循环更新时间、控制器任务周期、设备能力与通信监视时间。出现周期丢帧时先看端口链路、拓扑、负载和诊断计数，再决定是否调整工程参数。
5. 在批准的停机窗口模拟链路中断，验证输出替代值、报警、设备停机和受控恢复符合风险评估。

### 4. 现象到原因的初步分流

| 现象 | 优先排查 |
| --- | --- |
| DCP 能发现，控制器不建链 | 站名、GSDML、模块/字节长度、工程下载版本 |
| 输入变化但数值异常 | 类型、缩放、位号、字节/字顺序、机器人信号映射 |
| 间歇 I/O 丢失或设备掉线 | 端口诊断、线缆/屏蔽、拓扑、周期负载、监视时间 |
| 仅输出异常 | 输出地址、替代值、设备运行状态及安全/普通 I/O 边界 |

## 安全边界

PROFINET 普通过程数据不可替代 PROFIsafe 或经验证的硬接线安全功能。禁止通过延长监视时间、强制输出或屏蔽诊断来掩盖间歇掉线；这些操作会改变失效响应，必须经过项目风险评估和变更控制。
